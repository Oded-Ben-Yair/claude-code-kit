## ROOT CAUSE FOUND AND FIXED

**The Bug**: `elevenlabs.py` had two separate handlers:
- `committed_transcript` — **SILENTLY IGNORED** (did nothing)
- `committed_transcript_with_timestamps` — processed and published to event bus

**The Problem**: ElevenLabs sends `committed_transcript` (without timestamps) for real-time browser mic audio. So every transcription result was silently discarded.

**The Fix** (commit `602468d`): Combined both event types into a single handler:
```python
elif msg_type in ("committed_transcript", "committed_transcript_with_timestamps"):
```

**Why file upload worked but browser mic didn't**: File upload sends larger audio chunks that trigger the timestamp-enriched response. Real-time mic sends small 100ms chunks that get the simpler `committed_transcript` response.

## Session Discoveries & Learnings

### Critical Learnings
1. **ElevenLabs event types differ by audio mode**: Real-time mic gets `committed_transcript`, file/large-chunk gets `committed_transcript_with_timestamps`. Code must handle BOTH.
2. **Silent code paths are debugging poison**: `forward_audio()` had TWO paths that silently dropped ALL audio with zero logging. This made the bug invisible for multiple sessions.
3. **Instrumentation-first debugging works**: Adding counters + logging BEFORE guessing identified the exact failure point in one test cycle.
4. **Key Vault references don't resolve locally**: `.env` with `@Microsoft.KeyVault(...)` values won't work for local dev. Must `az keyvault secret show` to get actual values.
5. **Key Vault secret name is ELEVENLABS-API-KEY** (hyphenated uppercase), NOT ElevenLabs-ApiKey (CamelCase from docs).

### Patterns to Keep
- Debug counters (chunks_forwarded, chunks_dropped_status, chunks_dropped_scribe) — invaluable for live diagnostics
- Debug endpoint /api/session/debug/state — shows pipeline state at a glance
- Simulation script that mimics exact browser flow (cookie auth, PCM chunks)

### Patterns to Avoid
- Handling only one variant of an API event type (committed_transcript vs committed_transcript_with_timestamps)
- Assuming "file upload works = browser mic should work" (different ElevenLabs response types)
- Deploying fixes without verifying NEW log messages appear in production
