### Issue 1: Dual Language Display
- **Problem**: Both Arabic AND Hebrew text displayed, one line after another
- **Expected**: Only Hebrew text should be shown
- **Root cause**: Frontend `ws/transcript.py` publishes both `text_arabic` and `text_hebrew` in the segment, frontend renders both
- **Fix area**: Frontend rendering in transcript display component — filter to show only `text_hebrew`

### Issue 2: Timestamps Broken
- **Problem**: Timestamps jumping around (00:00:00, 00:00:01, 00:00:00, 00:00:11, 00:00:00, 00:00:20...)
- **Expected**: Sequential, cumulative timestamps matching audio position
- **Root cause**: Likely using per-segment timestamps from ElevenLabs Scribe v2 (relative to segment start) instead of absolute call time
- **Fix area**: `backend/app/services/elevenlabs.py` — timestamp handling in committed transcript events

### Issue 3: Word Looping / Duplication
- **Problem**: Same phrases appearing twice (e.g., "שלום עליכם" at 00:00:00 and again at 00:00:01)
- **Expected**: Each phrase appears once
- **Root cause**: Likely both partial AND committed transcripts being sent to translation, or event bus publishing duplicates
- **Fix area**: `backend/app/services/elevenlabs.py` — check if both partial and committed events trigger translation; `backend/app/services/translation.py` — check event subscription

### Issue 4: Translation/Transcription Accuracy
- **Problem**: Text not matching actual spoken Arabic content accurately
- **Expected**: Accurate Arabic transcription → accurate Hebrew translation
- **Root cause**: Could be audio quality (browser mic capturing played-back audio adds noise), Scribe v2 accuracy on phone call audio, or translation prompt issues
- **Fix area**: Test with raw audio upload instead of browser mic to isolate; check Scribe v2 language/model settings

### Issue 5: Latency and Flow
- **Problem**: Text appears in chunks, stiff, not flowing naturally as speech progresses
- **Expected**: Near real-time text appearing as words are spoken
- **Root cause**: Non-streaming translation (waits for full GPT response before showing Hebrew), plus Scribe v2 committed segments may batch too much text
- **Fix area**: Implement streaming translation (`stream=True` in `chat.completions.create`), publish partial Hebrew text via event bus as tokens arrive
- **User request**: "writing the Hebrew on screen as he writes it for real time near possible"

### Issue 6: Speaker Label "לא ידוע" (Unknown)
- **Problem**: All segments show "לא ידוע" (unknown speaker)
- **Expected**: Speaker identification (at minimum `rep` vs `customer`)
- **Root cause**: Known limitation — Scribe v2 Realtime has no `speaker_id`. Speaker is hardcoded to "unknown" in `translation.py:236`
- **Fix area**: Investigate dual-channel audio from VoiceSpin for speaker separation (v1.1 goal per CLAUDE.md)

## Learnings
- `anti-028`: Azure cognitiveservices endpoint (`*.cognitiveservices.azure.com`) works with `AsyncAzureOpenAI`; the `*.openai.azure.com` endpoint is the old format
- `anti-029`: GPT-5+ models do NOT support `temperature` parameter — will fail silently or throw
- `anti-030`: `gemini-2.5-flash` is NOT available through Azure AI Foundry — only through direct Gemini API
- `pattern-036`: `az webapp deploy` CLI may timeout (10 min) even when the app starts successfully — always verify with health endpoint independently
- `pattern-037`: Deploy zip for Azure Python App Service: `startup.sh` + `requirements.txt` at root, app code nested in package directory
