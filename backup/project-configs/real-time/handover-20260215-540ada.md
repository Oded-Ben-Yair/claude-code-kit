## Architectural Decisions

- **Batched rules**: All rules evaluated in ONE LLM call per segment (not N calls) — keeps cost and latency manageable
- **In-memory rules store**: MVP simplicity — rules lost on restart. Production should persist to Key Vault or DB
- **Fire-and-forget evaluation**: Evaluation failures never block transcription pipeline
- **Router prefix change**: `session_router` broadened from `/api/session` to `/api` to accommodate `/api/evaluation/rules`
