## P0 NEXT SESSION: 20-Round Deep Hostile Sprint

### Architecture: Per-Dimension Teams with Internal Fix-Review-Judge Loops

The next session is a fundamentally different approach. Instead of reviewing all 10 dimensions at once (which produces flat 7-8 scores), each dimension gets its own dedicated team that iterates internally until perfection.

### Round Structure (repeat 20x)

```
PHASE 1: Per-Dimension Deep Dive (10 parallel teams)
  ┌──────────────────────────────────────────┐
  │ For EACH of the 10 dimensions:           │
  │                                          │
  │   worker  → fixes code for this dim      │
  │   reviewer → hostile review (1 model)    │
  │   judge   → approve or reject            │
  │                                          │
  │   Loop: fix → review → judge             │
  │   Until: judge approves (max 3 cycles)   │
  │                                          │
  │   Output: reviews/round-N/dim-X.md       │
  └──────────────────────────────────────────┘

PHASE 2: Merge + Commit + Push
  - Merge all dimension fixes
  - Run full test suite
  - Commit + push to GitHub

PHASE 3: E2E Hostile Review (from GitHub URL)
  - 4-model hostile review of ENTIRE codebase
  - Review from GitHub raw URL (not local files)
  - Each model scores all 10 dimensions independently
  - Findings → reviews/round-N/e2e-{model}.md

PHASE 4: Learning Loop
  - /learning-loop with auto-approve
  - Extract patterns from this round's findings
  - Update agent prompts and team compositions
  - Tune reviewer rubrics based on what was found

PHASE 5: Report
  - Score trajectory update
  - Delta from previous round
  - Decision: continue or declare done
```

### Context Overflow Prevention (CRITICAL)

1. **Findings go to FILES, never parent context**: `reviews/round-N/dim-X.md`
2. **Lead reads ONLY summary files**: `reviews/round-N/summary.md` (max 30 lines)
3. **Each dimension team is ISOLATED**: worker+reviewer+judge in their own team, no cross-dim messages
4. **Pre-seed teams with prior findings**: Read `reviews/round-(N-1)/dim-X.md` at start
5. **Max 3 internal cycles per dimension**: Prevents infinite loops
6. **Session state saved to `.claude/status.json` after each round**: Enables resume on crash
7. **Stagger teams**: Run 3-4 dimension teams at a time (not all 10) to manage rate limits
