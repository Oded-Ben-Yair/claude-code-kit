## NEXT SESSION: Mother Terminal Orchestration

### Concept
User opens 4 Claude Code terminals in hey-seven:
- **Terminal M (Mother)**: Orchestrator. Does NOT write code. Plans, monitors, evaluates, guides.
- **Terminal 1-3 (Workers)**: Each owns specific files. Receives precise prompts from Mother (relayed by user).

### Mother Terminal's Job
1. **Brainstorm** the parallel plan with user (which terminal does what)
2. **Write initial prompts** for each worker terminal (user copy-pastes to other terminals)
3. **Define a shared status file** (e.g., `.claude/parallel-status.json`) that workers update after each deliverable
4. **Read status file** periodically to track progress across all terminals
5. **Review worker output** — user tells Mother "T1 finished X" and Mother reads the files to verify quality
6. **Orchestrate merge** — define merge order, resolve conflicts, run tests
7. **Run final eval** after all workers merge

### Shared Status File Pattern
```json
{
  "terminals": {
    "T1-comp-ltv": {"status": "working", "files_modified": [], "last_update": "..."},
    "T2-handoff": {"status": "done", "files_modified": ["handoff.py"], "last_update": "..."},
    "T3-profile": {"status": "working", "files_modified": [], "last_update": "..."}
  },
  "merge_queue": [],
  "eval_ready": false
}
```
Each worker writes their section. Mother reads the whole file.

### Recommended Mode: Start in PLAN MODE, then switch to EXECUTION
1. `/go` in **plan mode** — Mother brainstorms the full parallel strategy with user
2. User approves the plan
3. Mother exits plan mode, writes initial prompts for each worker terminal
4. User opens worker terminals, pastes prompts
5. Mother monitors via shared status file + user relay

### File Ownership (NO OVERLAPS)
| Terminal | Owns | Does NOT Touch |
|----------|------|----------------|
| T1 | dispatch.py, comp_strategy.py, ltv_nudge.py | profiling.py, handoff.py |
| T2 | handoff.py, crisis.py (handoff triggers) | dispatch.py, profiling.py |
| T3 | profiling.py, incentives.py, whisper_planner.py, extraction.py | dispatch.py, handoff.py |
| Mother | .claude/parallel-status.json, reviews/, eval scripts | ALL src/ files |

### _base.py Conflict Resolution
_base.py is touched by T1 (comp bridge) and T2 (handoff trigger). Options:
- **Option A**: T1 owns _base.py lines 1-200, T2 owns lines 200+. Fragile.
- **Option B**: T1 merges first, T2 rebases. Sequential for _base.py only.
