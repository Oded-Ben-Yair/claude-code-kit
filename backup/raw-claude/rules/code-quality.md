# Code Quality Rules

## Language Standards

### Python
- Formatter: `black` (line 88) | Linter: `ruff` | Type hints: required | Docstrings: Google style

### TypeScript
- Formatter: `prettier` | Linter: `eslint` | Named exports preferred

## Error Handling

Specific exceptions with context. Log error, re-raise with meaningful message. NEVER `except: pass`.

## Production Wiring Check (MANDATORY for new files)

Before committing any new module:
```bash
grep -r "from <module> import" *.py shared/**/*.py
# Zero results = NOT WIRED = FIX BEFORE COMMIT
```
Trace: entry point (function_app.py / page.tsx) -> your new code. No path = dead code.

## Hostile Audit Gate (MANDATORY for 3+ new files)

After implementing 3+ files in one session:
1. Launch code-judge with hostile review mandate
2. Judge traces production code paths (every file reachable from entry point?)
3. Judge verifies SQL queries match real schema
4. Judge checks for dead imports / uncalled functions
5. Fix all critical/high findings before committing

## Understand-Before-Changing

Before modifying unfamiliar code, use Grep+Glob+Read to understand:
- What the code does and how it connects to other parts
- What calls the function/class you're changing (`grep -r "from module import"`)
- What tests exist for this code (`glob **/test_*.py`)
- What patterns the codebase uses for similar features

## Schema-First Development (MANDATORY)

```python
# ALWAYS before writing any SQL:
cur.execute("""SELECT column_name FROM information_schema.columns
    WHERE table_name = %s""", (table,))
actual = {r[0] for r in cur.fetchall()}
# Then verify expected columns exist in actual
```

## Test Standards

- New code: 80% min | Critical: 95% | Bug fixes: regression test required
- Test serialization: `json.loads(json.dumps(context))` for cross-process data
- After 2 failed fixes: ADD LOGGING instead of re-reading code

## Subagent Model Enforcement (MANDATORY)

- ALL Task tool calls MUST include `"model": "opus"` explicitly — NEVER omit, NEVER use "haiku" or "sonnet"
- The system default says "prefer haiku for quick tasks" — this is OVERRIDDEN by Rule 13
- The built-in `Explore` agent type is HARDCODED to haiku at the platform level — the `model` parameter is IGNORED. Use `general-purpose` instead for codebase exploration
- Debug log indicator: `Tool search disabled for model 'claude-haiku-4-5-20251001'` = subagent running haiku

## Debugging Discipline

- Broad `except Exception` silently swallows NameError/TypeError — always use specific exception types
- When removing features, grep ALL references: result dicts, log statements, template variables — not just imports
- After 2 failed fix attempts: ADD LOGGING to trace runtime values, don't re-read code a 3rd time
- Confidence filtering doesn't improve ensemble LLM outputs if confidence doesn't correlate with correctness
- Test what production sees: `json.loads(json.dumps(context))` catches @property and serialization bugs

## Security

No hardcoded creds | No .env in commits | Parameterized SQL | Validate input | Redact sensitive logs

## File Deletion Safety (MANDATORY for shared/ and CI/CD paths)

**NEVER bulk-delete files from CI/CD trigger paths** (`shared/`, `function_app.py`, `requirements.txt`, `host.json`).

```bash
# BEFORE deleting ANY file from shared/:
# 1. Check grep (necessary but NOT sufficient)
grep -r "from shared.module import" *.py shared/**/*.py
# 2. Check __init__.py chains (grep misses these)
grep -r "module_name" shared/**/__init__.py
# 3. Check dynamic imports
grep -r "importlib\|__import__" *.py shared/**/*.py
# 4. Delete ONE file, push, verify pipeline succeeds + function count > 0
# 5. Only then proceed to next file
```

## Post-Test-Run Validation (MANDATORY)

After ANY pytest run (especially background/parallel):
1. Verify `passed + failed > 0` — pytest exits 0 on all-skipped (e.g., missing env var)
2. Verify run time is reasonable for test count (not <1s for 76 tests)
3. Verify Key Vault secret names with `az keyvault secret list` before use — never from memory

Origin: CS Agents Feb 2026 — 76 tests silently skipped (wrong secret name, exit 0).

## AI-Generated Research Verification (MANDATORY)

Research facts generated by LLMs MUST be verified against primary sources before inclusion in any deliverable:
- Financial figures: Check Wikipedia, SEC filings, press releases
- Legal citations: Check court records, law firm alerts
- Regulatory status: Verify rules are still in effect (not vacated/overturned)

Origin: Hey Seven R1 2026-02 — 5 critical factual errors caught. AI-generated research was plausible-sounding but wrong.

**Statute/regulation references are HIGH RISK** — LLMs frequently cite the correct code section number but wrong subsection or program. Example: NRS 463.368 governs involuntary exclusions (cheating), not voluntary self-exclusion (NGC Reg. 5.170). Both are "Nevada gaming law" but serve completely different purposes. For regulated domains (casino, healthcare, finance), verify EVERY statutory reference against the actual regulation text.

Origin: Hey Seven R57 (2026-02-25) — Grok caught incorrect NRS 463.368 reference that persisted through 5 review rounds.

## Async Migration Safety (MANDATORY)

When converting sync functions to async:

1. **Grep ALL callers** of the function being converted
2. **Add `await` to every call site** — missing `await` returns a coroutine object, not the result
3. **Check `except Exception` handlers downstream** — they silently swallow the breakage
4. **Convert lock types consistently** — `threading.Lock` in async code deadlocks; `asyncio.Lock` in sync code crashes
5. **Run tests for EACH converted caller**, not just the function itself

Origin: Hey Seven R18-R19 — async migration broke 2 downstream callers. `except Exception` masked the breakage.

## Documentation Honesty Vocabulary (MANDATORY)

| Term | Meaning |
|------|---------|
| **Implemented** | Code exists AND is called from production code path |
| **Wired** | Code exists AND is connected to the graph/pipeline/entry point |
| **Scaffolded** | Code exists but NOT called from any production path |
| **Planned** | No code exists, design documented |

Documentation that overclaims is WORSE than documentation that underclaims.

Origin: Hey Seven R1-R2 — overclaiming "implemented" for scaffolded features was the single largest scoring differential (15-20 points).

## Deterministic Tie-Breaking in Max/Sort (MANDATORY for dispatch/routing)

Always add secondary sort key when using `max()` on dicts for routing or dispatch decisions:

```python
# BAD: Non-deterministic on ties
winner = max(counts, key=lambda k: counts[k])

# GOOD: Alphabetical tie-breaking
winner = max(counts, key=lambda k: (counts[k], k))
```

Without secondary key, `max()` returns first key in dict insertion order (non-deterministic).

Origin: Hey Seven R20 — specialist dispatch was non-reproducible due to tied keyword counts.

## Immutable Module-Level Defaults

Wrap module-level `DEFAULT_*` dicts in `types.MappingProxyType` to prevent accidental mutation:

```python
from types import MappingProxyType
DEFAULT_FLAGS = MappingProxyType({"feature_a": False, "feature_b": True})
```

Add parity assertion: `assert set(TypedDict.__annotations__) == set(DEFAULT_X.keys())` to catch drift.

Origin: Hey Seven R20 — mutable defaults risk cross-thread corruption in async LangGraph applications.

## Placeholder Response Tracking (MANDATORY)

Never ship placeholder API responses (`{status: 'coming_soon'}`) without:
1. A tracking ticket with a due date
2. A TODO comment in code with the ticket ID
3. A log warning when the placeholder is served

Better: implement the feature before shipping the endpoint, or return HTTP 501 Not Implemented.

Origin: Sentimark Feb 2026 — leaderboard weekly/all_time returned "coming_soon" for months. No one tracked or noticed.

## Processing Order Matters for Safety Pipelines (MANDATORY)

When a response passes through multiple post-processing stages (PII redaction, branding, personalization, truncation), the order is critical:

1. **Safety-critical first** (PII redaction, compliance) — fail-closed
2. **Branding enforcement** (exclamation limits, emoji removal) — best-effort
3. **Personalization** (guest name injection) — only if name not already present
4. **Truncation** (SMS length limits) — always last

Never run personalization before safety — injected names could bypass PII redaction.

Origin: Hey Seven Phase 4 (2026-02-22) — persona_envelope_node processing order: PII → branding → name → SMS.

## Schema-Dispatching Mock LLM for Multi-Node E2E Tests (Pattern)

When testing a LangGraph graph end-to-end with mocked LLMs, a single mock must handle multiple `with_structured_output()` calls with different Pydantic schemas (RouterOutput, DispatchOutput, ValidationResult, etc.). Build a smart mock that dispatches by schema type:

```python
class _SmartMockLLM:
    def with_structured_output(self, schema, **kwargs):
        if schema == RouterOutput:
            return _MockThatReturns(RouterOutput(query_type="property_qa", confidence=0.95))
        elif schema == ValidationResult:
            return _MockThatReturns(ValidationResult(status="PASS", reason="OK"))
        elif schema == DispatchOutput:
            return _MockThatReturns(DispatchOutput(specialist="dining", confidence=0.9, reasoning="food query"))
        # ... handle ALL schemas the graph uses
```

Key: if ANY schema is missing, the node that uses it will fail silently or fail-closed (e.g., semantic injection classifier blocks all messages). Trace every `with_structured_output()` call in the codebase before writing E2E tests.

Origin: Hey Seven Phase 5 (2026-02-22) — E2E tests failed until InjectionClassification schema was added to mock. Classifier fail-closed and blocked all messages.

## Hook-Trigger Word Awareness in Task Subjects (Pattern)

TaskCompleted hook scans task subjects for trigger words (deploy, pipeline, push). Tasks that contain these words trigger deployment verification even for local-only work. Avoid trigger words in task subjects for non-deployment tasks, or rename if blocked.

Origin: Hey Seven Phase 5 (2026-02-22) — "RAG pipeline improvements" triggered deploy verification hook. Renamed to "RAG ingestion improvements" to unblock.

## Infrastructure-Without-Wiring Anti-Pattern (MANDATORY for performance/refactor work)

When creating utility code (hooks, helpers, abstractions) as part of a performance optimization or refactor:

1. **For each utility created**: immediately wire it to at least ONE consumer in the same session
2. **Count the gap**: if N utilities created but M consumers migrated, and M < N, the work is INCOMPLETE
3. **Verify the consumer changed behavior**: build pass is insufficient — measure the actual metric (API call count, bundle size, SSR output, cache hit rate)
4. **Architectural changes require full propagation**: removing `'use client'` from a layout only helps if providers are extracted. Adding SWR hooks only helps if pages import them instead of raw fetch.

**The 4 traps** (each individually insufficient without wiring):
- Creating hooks without migrating pages = no caching benefit
- Adding dynamic imports without removing `'use client'` on layout = no SSR benefit
- Removing dead code without fixing bottleneck API calls = no performance benefit
- Adding loading skeletons without caching = skeleton shown but data still slow

Origin: Sentimark Feb 2026 — Session created 16 SWR hooks, added dynamic imports, removed 17K LOC dead code, added skeletons. Site still slow because: hooks not wired to 5 pages, layout still `'use client'`, 32 API calls remained. Next session wired everything in 1 hour and it worked immediately. The infrastructure was correct — only the last-mile wiring was missing.

## Never Return Mutable Module-Level Data (MANDATORY)

Functions that return module-level dicts/lists MUST return `copy.deepcopy()`. A caller mutating the return value corrupts global state for ALL subsequent requests in the same process.

```python
# BAD: Returns mutable reference to global dict
def get_config(id):
    return CONFIGS.get(id)  # Caller mutation corrupts CONFIGS

# GOOD: Returns deep copy
def get_config(id):
    import copy
    return copy.deepcopy(CONFIGS.get(id))
```

Fix BOTH paths: the happy path (known ID) AND the fallback path (unknown ID → default). R35 only fixed the fallback, R36 caught the happy path — 1 round of production-corrupting bug.

Origin: Hey Seven R35-R36 Sprint — `get_casino_profile()` returned mutable CASINO_PROFILES dict. Any request mutating branding data corrupted it for all subsequent requests.

## Multi-Layer Input Normalization for Security (MANDATORY)

When validating user input against patterns (guardrails, allowlists, blocklists), normalize ALL encoding layers BEFORE matching:

```python
def normalize_input(text: str) -> str:
    # 1. URL decode (iterative for double-encoding, max 3 passes)
    prev = text
    for _ in range(3):
        decoded = urllib.parse.unquote_plus(prev)
        if decoded == prev:
            break
        prev = decoded
    # 2. HTML entity decode
    text = html.unescape(prev)
    # 3. Unicode NFKC normalize
    text = unicodedata.normalize("NFKC", text)
    # 4. Strip invisible Unicode (Cf category)
    text = "".join(c for c in text if unicodedata.category(c) != "Cf")
    return text
```

**Order matters**: URL decode → HTML unescape → NFKC → Cf strip. Wrong order = bypass.
**Iterative unquote**: Single-pass misses double-encoding (`%2520` → `%20` → ` `).
**unquote_plus not unquote**: Form-encoded `+` must decode as space.

Origin: Hey Seven R35-R39 Sprint — 4 consecutive CRITICALs: Unicode Cf bypass (R35), URL encoding bypass (R38), double-encoding bypass (R39), form-encoded + bypass (R39).

## Rename Propagation Check (MANDATORY after refactoring)

After renaming any attribute, variable, or method, grep ALL references including:
- String-based access (`getattr(obj, "old_name")`, `obj["old_name"]`)
- Cross-file references (other modules importing/referencing)
- Test files and fixtures
- Config files and documentation

```bash
grep -rn "old_name" --include="*.py" src/ tests/
```

A missed rename produces `AttributeError` at runtime, not at import time. Tests may not cover the path.

Origin: Hey Seven R45 — R39 renamed `_lock` to `_requests_lock` in RateLimitMiddleware, but `app.py:220` still referenced `middleware._lock`. `/metrics` endpoint crashed. Found 6 rounds later.

## TTLCache Jitter for Singleton Caches (MANDATORY for 3+ caches)

When multiple singleton caches share the same TTL, they expire simultaneously causing thundering herd. Stagger TTLs:

```python
import random
_BASE_TTL = 3600
_llm_cache = TTLCache(maxsize=1, ttl=_BASE_TTL + random.randint(0, 300))
_config_cache = TTLCache(maxsize=100, ttl=_BASE_TTL + random.randint(0, 300))
```

Origin: Hey Seven R40 — 6 TTLCache singletons with identical ttl=3600. Under load, all expired within the same second, causing 6 parallel cold-start initialization races.

## Test Auth Fixtures Must Match Middleware (MANDATORY)

When adding authentication middleware, update test conftest IMMEDIATELY — not "later":

```python
@pytest.fixture(autouse=True)
def _disable_auth_in_tests(monkeypatch):
    monkeypatch.setenv("API_KEY", "")
    # Clear cached settings that read the env var
    get_settings.cache_clear()
```

Origin: Hey Seven R40 — ApiKeyMiddleware added but test helpers not updated. 52 tests failed with 401 for 5 rounds before being diagnosed. The "pre-existing failures" were actually a test infrastructure bug.

## SRP Refactor: Extract at 100+ LOC (MANDATORY)

Functions exceeding 100 LOC that mix 3+ responsibilities MUST be refactored into focused helpers:

```python
# Pattern: thin orchestrator + focused helpers
async def orchestrate(state):       # ~30 LOC: calls helpers in sequence
    name = _route(state)             # ~60 LOC: routing logic only
    state = _prepare(state, name)    # ~25 LOC: state injection only
    return _execute(state, name)     # ~55 LOC: execution + error handling
```

Don't defer — carried SRP debt accumulates review penalties every round (+1 MAJOR per round it's unfixed).

Origin: Hey Seven R34-R43 — `_dispatch_to_specialist` (195 LOC) flagged as MAJOR for 9 consecutive rounds. Each round's reviewers penalized it more harshly. Refactor took 1 focused round.

## Key Anti-Patterns

- Unit tests pass != integration works (test full call chains with real data)
- "Code written" != done (verify with real data in production)
- grep zero imports ≠ safe to delete (check __init__.py, dynamic imports, module scanning)
- Pipeline status=completed != output correct (verify segment counts, label counts, length ratios)
- `os.environ.setdefault()` in test files != reliable isolation (use monkeypatch fixture + cache clear)
- Feature flag = False + wired code = dead code (default must be True if code is wired)
- Function returns input unchanged = no-op (trace runtime path, not just read source)
- Review rubric measures code quality only != measures agent quality (use 40/60 rubric for AI agents)
- execute_specialist() in isolation != full graph works (test build_graph() + chat() with mocked LLMs)
- Score plateau (3+ rounds within +/-2 points) = time to change strategy, not repeat same approach
- NaN in regression detection silently passes (always guard float comparisons with math.isnan)
- Baseline margin < threshold = non-functional gate (ensure baseline - actual > detection threshold)
- LLM output dimensions mapped to unrelated metric names = silent data corruption (groundedness mapped to "empathy" means empathy scores are actually groundedness scores — any decision based on that metric is wrong)
- Teammate implements code, lead commits without reading = 3 CRITICALs shipped (always review teammate output before committing)
- Infrastructure created but not wired = zero user-visible improvement (creating 16 SWR hooks without migrating pages, adding dynamic imports without removing 'use client' on layout, removing dead code without fixing 32-API-call bottleneck). Always verify the CONSUMER is connected, not just that the UTILITY exists.
- Optimization claimed without runtime verification = false confidence (build passes + HTTP 200 ≠ performance improved. Measure actual request count, cache hits, SSR output, load time)
- Internal review score 96 != external score 96 (self-review has calibration drift — always validate with fresh external models before claiming quality)
- asyncio.to_thread() for I/O libraries = wrong fix (use native async client: redis.asyncio, aiohttp, etc. to_thread exhausts thread pool under concurrent load)
- 90% test coverage with auth/security disabled = fake coverage (tests must exercise production code paths, not neutered versions)
- "Fixed the finding" without validating the fix approach = potential regression (R46 moved Redis inside lock per reviewer suggestion; R47 flagged lock+I/O as CRITICAL. Validate fix approach with external model.)
- Warn-not-strip for unauthorized state mutations = TOCTOU vulnerability (if code shouldn't write a key, strip it — don't log a warning and continue)
- Normalization applied to stored text = data destruction (O'Connor→OConnor, emails stripped. Normalization is for pattern matching ONLY, never for state/response text)
- 45 rounds of same-model review = diminishing returns on NEW categories (finds more of the same type of issue, misses entirely new categories. Use multi-model gate after 10 rounds.)
- Return value changed without tracing consumers = cross-file logic bug (confidence=0.5 set in guardrails.py, but compliance_gate.py checks >= 0.8 — fix was effectively fail-OPEN. Always grep ALL callers when changing a return value.)
- Sentinel/constant type changed without checking serialization = production crash (object() sentinel is collision-proof but doesn't survive JSON/Firestore roundtrip. Always ask: "does this value cross a serialization boundary?")
- Detection added without response handler = worse than no detection (self-harm detected by compliance_gate but off_topic_node had no case → suicidal guests got "I'm your concierge". When adding a new query_type, grep ALL node handlers.)
- Fix resolves one concern but creates opposite concern = need third option (R47 fail-closed=DoS, R48 fail-open=bypass. Restricted mode resolves both. When two reviewers disagree, the answer is usually a third design, not picking a side.)
- Parallel implementation waves + parallel doc updates = doc-code parity drift (Wave 5 docs used stale numbers because Wave 1 code changes ran simultaneously. Make doc waves depend on code wave completion for shared data like pattern counts, helpline numbers.)
- New behavior added without test = MAJOR in next review (R68: ETag/304 added in Wave 4 with "don't modify tests" instruction → GPT-5.3 flagged as MAJOR. Every wave that adds behavior MUST include tests in scope.)
- Security metric claims not verified by CI = 3-way count drift (R68: pattern count was 171, 185, and 204 across 3 documents. Add `assert len(patterns) == N` test and reference it in docs to prevent drift.)
- New module at 0% coverage silently drops total below threshold (R68: validators.py added without tests → 89.43% < 90% gate. Always create test file alongside new module.)
- Normalization applied to only ONE guardrail category = all others bypassable (R50: injection normalized but RG/BSA/age/privacy didn't. URL encoding bypasses responsible gaming detection just as easily as injection. Normalize at the shared helper level, not per-category.)
- Parity-sensitive value changed in one file but not propagated = reviewer finds 5+ MAJORs (R69: VERSION 1.1.0→1.3.0 changed in config.py but not .env.example, middleware header, runbook. Pattern count 204→205 changed in runbook but not README, ARCHITECTURE, ADR-018, fuzz test docstring. Tribal URL fixed in config but not prompts, data JSONs, knowledge-base, jurisdictional-reference. After ANY parity-sensitive value change: `grep -rn "OLD_VALUE" --include="*.py" --include="*.md" --include="*.json" --include="*.yaml" src/ tests/ docs/ data/ knowledge-base/` and fix ALL hits.)
- Scaffolded code claimed as "implemented" = false confidence for N review rounds (R68: validators.py created with tests but zero src/ imports. R69 Gemini caught it as dead code. grep `from src.X import Y` in src/ — zero hits = scaffolded, not implemented.)
- Extract-to-helper refactor breaks when variables are defined AFTER the call site (R72: moved behavioral signals to `_build_behavioral_prompt_sections()` but `user_msg` was computed inside the old code block. `history` was only needed for the sliding window section but was defined inside the extracted block. Always trace variable dependencies BEFORE extracting, not after.)
- Collection type choice for accumulated state must consider serialization boundary (R72: `domains_discussed` uses `list[str]` not `set[str]` because LangGraph checkpointer serializes to JSON/Firestore. `set` → `TypeError: Object of type set is not JSON serializable`. Always use `list` with dedup reducer for state fields that cross serialization boundaries.)
- Slang normalization must handle contractions and suffixes (R72: "YOLO'd" failed lookup because `rstrip` removed `'` but not `d`. Handle `'d`, `'s`, `'t` as contraction suffixes separately from punctuation stripping.)
- Research-first code design prevents building the wrong thing (R72 A6: research showed production systems DON'T classify sarcasm — they design sarcasm-resilient responses. Without research, would have built an expensive LLM classifier. Research changed the architecture from "detect sarcasm" to "respond empathetically by default when context is negative.")
- LLM system prompt tone = output tone (R73: "warmest, most knowledgeable person" + "genuine enthusiasm" → "Oh, I'd be absolutely delighted." Production fix: "warmth from SUBSTANCE not ENTHUSIASM" + "NEVER start with Oh,". Prompt tone directly controls output register — test with live LLM, not mocks.)
- Scenario count from memory != actual count (R72: handover said 80, actual `grep "^  - id:" | wc -l` = 74. Always verify counts with code, not memory.)
- 3-model parallel MCP judging is efficient (R72: Gemini Pro + GPT-5.2 + Grok 4 via MCP tools, 20 scenarios per batch, ~5 min total. ICC(2,1) = 0.797. Reusable pattern for any behavioral evaluation.)
- Mock behavioral score ≠ live behavioral score (R75: mock 8.15 vs live 5.8 = 29% overestimate. Same gap as R72: 7.3→4.1. Mock tests don't exercise router→dispatch→specialist with real LLM. ALWAYS validate behavioral quality with live agent before claiming behavioral scores.)
- Broad guardrail regex matches unrelated categories = safety misfire (R75: `\bis\s+[\w\s]+here` in patron privacy matched crisis follow-up "Is there someone I can talk to here?". When adding guardrail patterns, test against ALL other categories' test phrases. Position-based short-circuiting means first match wins — wrong category = safety violation.)
- Pydantic schema complexity invisible to mock tests = 100% production failure (R76: 3236 tests passed while 3 Gemini structured output schemas were completely broken. Mocks bypass schema validation — add @pytest.mark.live tests for every with_structured_output() call.)

- Feature flag added to DEFAULT_CONFIG but not CASINO_PROFILES = parity test failure (R98: `model_routing_enabled` added to `DEFAULT_FEATURES` and `DEFAULT_CONFIG` but not to 5 casino profiles. - Assuming AGENCY is the gap when RELATIONSHIP is the gap (R101: Gold traces showed decisive "I've got you" behavior. Oded showed the real gap is profiling-through-conversation — "What are we celebrating?" BEFORE "I've got you at MJ's". The agent doesn't try to KNOW the guest.)
